Mobile app setup

The viewer app is a Flutter project: one codebase that builds both the Android and the iOS app. You set it up on your own computer, point it at your server, give it your name and look, and build the release files you upload to Google Play and the App Store.

What you need on your computer​

ToolVersionWhy
Flutter3.47.7 exactly (the project pins it in .fvmrc)Builds the app.
Dart3.13 or newer (comes with Flutter)Flutter's language.
Android StudioA recent versionAndroid SDK, emulator and signing tools.
Java (JDK)17 or newerNeeded by Android's build tools.
XcodeA recent version, on a MacOnly for the iOS app.
CocoaPodsA recent version, on a MacInstalls iOS libraries.
Firebase CLI and FlutterFire CLILatestConnect the app to your Firebase project (Firebase).

The app runs on Android 7.0 and newer and iOS 15 and newer, on phones and tablets. Installing and checking these tools step by step: Set up Flutter.

Use FVM to get the exact Flutter version

FVM (Flutter Version Management) reads .fvmrc and installs the matching Flutter for this project only: fvm install then use fvm flutter instead of flutter. Using a different Flutter version is the most common cause of build errors.

info

Setting up Flutter, Android Studio and Xcode on your computer is done once and follows the official guides: Flutter install, Android Studio, Xcode.

The roadmap​

  1. Set up Flutter and the Android and iOS tools on your computer.
  2. Give it your package name first: Firebase and the stores are tied to it.
  3. Connect Firebase: the app doesn't build or start without its files.
  4. Connect it to your server by changing two addresses, then run it on an emulator or your phone.
  5. Make it yours: name, logo and icons, colours and fonts, defaults and languages.
  6. Connect services: push notifications, ads, in-app purchases and share links.
  7. Get ready to release: check the permissions and platform settings, set up signing and certificates, and build the release.
  8. Publish to the stores, then tell your server about the new version.

Every file you'll change​

The project keeps everything a rebrand touches in a handful of files, each marked Reskin here at the top. You don't need to edit any screen code.

To changeEdit
App name, server address, share domain, default theme and accent, sign-in methods, screen protectionlib/app/config/app_config.dart
Firebase keyslib/app/config/firebase_options.dart (generated), android/app/google-services.json, ios/Runner/GoogleService-Info.plist
Colourslib/core/theme/theme_colors.dart
FontsAppFonts in lib/core/theme/app_typography.dart, and fonts: in pubspec.yaml
Defaults and limitslib/core/constants/constant.dart
Logo, coin, VIP badge, company logoThe files in assets/branding/ (keep the same names)
App iconThe files in assets/branding/launcher/, then dart run flutter_launcher_icons
Iconslib/core/constants/app_icons.dart
API pathslib/core/network/api_endpoints.dart (only if your server's differ)
English textassets/l10n/template.json
Name under the iconandroid/app/src/main/AndroidManifest.xml, ios/Runner/Info.plist
Package name / bundle IDandroid/app/build.gradle.kts, the MainActivity.kt folder, Xcode
Share and website link domainsandroid/app/build.gradle.kts, ios/Runner/Runner.entitlements

Prices, coin amounts, ad limits, VIP plans, feature switches and every language except English are not in the app: they come from your Admin Panel, so you change them without releasing a new version.
