Build the release

This page builds the files you upload to the stores. Signing is set up once on Signing & certificates; uploading and store review are on Publish to the stores.

Version numbers​

The version lives in one place, pubspec.yaml:

pubspec.yaml
version: 1.0.1+2
PartHereAndroidiOSRule
Version name1.0.1versionNameCFBundleShortVersionStringWhat viewers see. Also what you enter as Latest in the Admin Panel.
Build number2versionCodeCFBundleVersionMust be higher for every upload, even a re-upload of the same version.

The build reads both from pubspec.yaml: don't edit them in Gradle or Xcode.

Before you build​

  • The app points at your server (Connect to your server).
  • Name, package name, logo, icons and colours are yours.
  • Firebase is connected and the sign-in methods are on (Firebase).
  • Your AdMob app IDs replace the test IDs (Ads).
  • Your own shareHost, websiteHost and applinks: domains replace your-domain.com (Deep links).
  • flutter analyze prints "No issues found!" and flutter test passes.
  • The version is raised in pubspec.yaml: version: 1.0.0+1 means version 1.0.0, build 1. Every upload to a store needs a higher build number.

Android: create your signing key​

Google Play needs every update signed with the same key. Create it once and keep it safe: if you lose it, you can't update your app.

Terminal
keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

Copy android/key.properties.example to android/key.properties and fill it in (never share it or commit it to version control; the download's android/.gitignore already leaves out key.properties and *.jks):

android/key.properties
storeFile=/Users/you/upload-keystore.jks
storePassword=your-store-password
keyAlias=upload
keyPassword=your-key-password
admob.appId=ca-app-pub-1234567890123456~1234567890

storeFile is read from the android/app/ folder when it's a plain file name; a full path works too. The build reads this file automatically. Without it, a release build is signed with the debug key, which Google Play refuses.

iOS: choose your team​

Open ios/Runner.xcworkspace in Xcode, select Runner › Signing & Capabilities and pick your Team for the Release configuration. The download has none, so flutter build ipa fails until you do.

Build​

The project includes tool/build_release.sh, which runs flutter build <target> --release --obfuscate --split-debug-info=build/debug-info: obfuscated Dart code, with the debug symbols kept separately in build/debug-info for crash reports. Clean once before a store build:

Terminal, in the app folder
flutter clean && flutter pub get
  • Google Play (.aab)
  • App Store (.ipa)
  • APK (direct download)
Terminal
tool/build_release.sh appbundle

Upload build/app/outputs/bundle/release/app-release.aab in Play Console (Publish to the stores). Google Play only accepts app bundles (.aab), signed with your upload key (Signing). R8 also shrinks and obfuscates the Android code; Crashlytics uploads its mapping file by itself.

Two ways, both on a Mac, with your Team chosen in Xcode (Signing):

From the terminal

Terminal
cd ios && pod install && cd ..
tool/build_release.sh ipa

The file is build/ios/ipa/*.ipa. Upload it with Apple's Transporter app (sign in, drag the .ipa in, Deliver).

From Xcode

  1. flutter build ios --release --obfuscate --split-debug-info=build/debug-info
  2. Open ios/Runner.xcworkspace, choose Any iOS Device (arm64) as the destination.
  3. Product › Archive. When the Organizer opens: Distribute App › App Store Connect › Upload.

Make sure Xcode shows Push Notifications, Background Modes, Sign in with Apple, Associated Domains and App Attest under Signing & Capabilities.

Terminal
tool/build_release.sh apk

The file is build/app/outputs/flutter-apk/app-release.apk. Useful for testing, or for the website's direct-download button.

Test the release build first​

Run it on a real phone before uploading: release builds behave differently from debug ones (no debug banner, real App Check, real ads once your IDs are set).

Terminal
flutter run --release

Check sign-in, an episode playing, a purchase with a test account, a push, and a shared link.

If a release build fails​

ErrorFix
Keystore file not found / keystore password was incorrectCheck storeFile and the passwords in android/key.properties (Signing).
Play Console: You uploaded an APK or Android App Bundle that was signed in debug modeandroid/key.properties is missing, so the debug key was used.
Play Console: Version code 1 has already been usedRaise the number after + in pubspec.yaml.
WARNING: this release build uses Google's TEST AdMob app IDSet admob.appId (Ads setup).
No profiles for '…' were found / Signing requires a development teamPick your Team in Xcode › Signing & Capabilities.
pod install errorscd ios && pod repo update && pod install. On Apple silicon, update CocoaPods first.
File google-services.json is missingRun flutterfire configure (Firebase).

Keep the debug symbols​

Keep build/debug-info for every release you ship: stack traces from an obfuscated build can only be read with it. To see readable Dart stack traces in Crashlytics, upload it with the Firebase CLI:

Terminal
firebase crashlytics:symbols:upload --app=<your Firebase app ID> build/debug-info

After the first Google Play release​

Google Play signs the app it delivers with its own app signing key. Copy that key's SHA-256 from Play Console › Test and release › App integrity › App signing, then:

  • add it to EDRAMA_ANDROID_SHA256 in the server's .env, after your upload key's and separated by a comma, so share links keep opening the app (Deep links);
  • add it (and its SHA-1) to your Android app in Firebase, so Continue with Google works for Play installs (Firebase).

After publishing: tell the server​

Open Admin Panel›Settings›App & support›App versions and, for each platform, fill in:

FieldMeaning
LatestThe version you just published. Viewers on older builds are offered the update.
Minimum supportedBuilds below this must update before they can use the app. Raise it only when an old build breaks something.
Store linkYour app's Google Play or App Store page. Used by the update screens, share pages and the website's store buttons.

The On latest column shows how many devices seen in the last 30 days run the latest version.

Store listing reminders​

  • Google Play's Data safety form and Apple's App Privacy answers must cover sign-in (email, phone), purchases, ads (AdMob) and crash reports (Crashlytics).
  • Link your privacy policy: https://admin.your-domain.com/legal/privacy (published from Admin Panel›Settings›Legal pages).
  • If you use YouTube episodes, your privacy policy must say the app uses YouTube API Services and link to Google's privacy policy (YouTube).
  • Store reviewers need to sign in. Create an email-and-password account for them on the server with php artisan edrama:review-account (Server commands) and put it in Play Console (App content › App access) and App Store Connect (App Review Information).
  • Apple reviewers can buy with their sandbox account; nothing needs switching on the server.
  • WRTeam's common guide walks through the store listings: Play Store and App Store.
