The installer gives you a working Admin Panel. These steps make it ready for real viewers. Do them in this order.

## 1. Sign in

Open `https://your-domain.com/admin` (the domain's root address also takes you there) and sign in with the Owner email and password you chose in the installer.

## 2. Check the server's health

Open <Path>System › System</Path>. Look for:

- **Cron running** in green. If not, add the [cron line](cron-and-queues.mdx).
- No red warning cards. The page warns you if:
  - the `.env` file can be opened from the web,
  - the server isn't set up as a live server (`APP_ENV` or `APP_DEBUG`),
  - visitors reach the app through a proxy it doesn't trust.

Each warning names the exact line to change.

## 3. Protect the Owner account

Open your name at the foot of the sidebar › **Your account** and set up **two-factor authentication**. See [Sign-in & your account](../admin/sign-in-and-account.mdx).

## 4. Connect email

Without email, team invites, password resets and creator emails can't be sent. Open <Path>Settings › Email delivery (SMTP)</Path>, enter your provider's details and choose **Send test email**. See [Email](../admin/settings/email.mdx).

## 5. Connect Firebase

Viewer sign-in, the Creator Portal's sign-in and push notifications all need Firebase. Open <Path>Settings › Notifications</Path>, fill in the Firebase card and choose **Test connection**. See [Firebase](../integrations/firebase.mdx).

## 6. Make it yours

- <Path>Settings › Branding</Path>: app name, logos, theme colour.
- <Path>Settings › App & support</Path>: support email, store links.
- <Path>Settings › Legal pages</Path>: terms, privacy policy, refund policy and Creator Terms.

## 7. Check video

Open <Path>Settings › Storage & video</Path>. The **This server** option should show ffmpeg in green, or set up another option. Upload one short test episode and watch it reach **Ready**.

## 8. Remove the demo data

If you imported demo data, look around first, then remove it before launch with <Path>System › Clear demo data</Path>. See [Clear demo data](../admin/system/clear-demo-data.mdx).

Continue with the [Launch checklist](../getting-started/launch-checklist.mdx) for money, content and the app.

## Useful commands

You'll rarely need these, but they're good to know. Run them in the project folder. Every command, including the store reviewer account and Cloudflare Stream's webhook, is on [Server commands](commands.mdx).

| Command | What it does |
|---|---|
| `php artisan edrama:create-owner` | Creates the Owner if the installer didn't (reads `EDRAMA_OWNER_*` from `.env` when run without a terminal). |
| `php artisan edrama:demo-data` | Imports the demo data. |
| `php artisan config:cache` | Applies changes to `.env`. |
| `php artisan queue:restart` | Makes the workers reload after a change or update. |
| `php artisan optimize` | Speeds up the app after an update. |
| `php artisan edrama:repair-encryption` | Clears saved secrets that can no longer be read because `APP_KEY` was lost, so you can enter them again. |
