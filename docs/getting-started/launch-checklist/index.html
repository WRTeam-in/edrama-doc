Launch checklist

Use this page as your map. Each line links to the page with the full instructions. Tick them off in order: later steps depend on earlier ones. Your ticks are saved in this browser, so you can come back to it as you work.

1. Server

0/5
  • Rent a server that meets the requirements (PHP 8.5, MySQL 8, HTTPS, ffmpeg or Cloudflare Stream) and point your domain at it.
  • Prepare it: VPS or shared hosting. The domain points at the package's public folder only.
  • Run the web installer: requirements, purchase code, database, Owner account.
  • Add the cron line and queue workers, then check Admin Panel›System›System shows "Cron running".
  • Make sure ffmpeg works (or choose Cloudflare Stream) and a test episode reaches Ready.

2. Admin Panel basics

0/9
  • Sign in as the Owner and turn on two-factor.
  • Set your branding: app name, logos, favicon, theme colour.
  • Add your SMTP email server and send a test email.
  • Add the Firebase keys and press Test connection.
  • Set your support email. Until you do, the app shows support@example.com.
  • Choose where files and videos live.
  • Publish your legal pages, including the Creator Terms.
  • Upload the app file for every language you offer, or turn Hindi off (a fresh install lists it as offered).
  • Invite your team with the right roles, and require two-factor for everyone.

3. Money

0/6
  • Review your regions: currency, coin value and countries.
  • Add exchange rates for every currency you sell in.
  • Set your coin packs and VIP plans per region.
  • Create the same products in Google Play and the App Store, paste the store keys in Admin Panel›Settings›Payments, and set up both stores' server notifications.
  • If you use ads, set up AdMob with server-side verification on every ad unit.
  • Set the creator share and store fees.

4. Content

0/5
  • Review the categories.
  • Create your first titles, upload episodes and set prices.
  • Schedule the episodes.
  • Build the app's Home and publish it.
  • Remove the sample content with Clear demo data if you imported it.

5. Mobile app

0/12
  • Set up Flutter and the Android and iOS tools, and read what's in the download.
  • Change the package name first: Firebase and the stores are tied to it.
  • Connect Firebase (the build stops without its files), fill in the iOS URL schemes and turn on the sign-in methods you offer.
  • Connect the app to your server, then run it.
  • Change the name, logo and icons and colours.
  • Upload your APNs key to Firebase and send yourself a test push.
  • Replace Google's test IDs with your AdMob app IDs.
  • Set up share links, and check both .well-known files on your server show your app.
  • Create and back up your upload keystore, and add every SHA fingerprint to Firebase.
  • Build the release, create a store reviewer account and publish it to the stores.
  • Enter the store links and versions in Admin Panel›Settings›App & support.
  • Once the store build works, turn on App Check: monitor first, then enforce.

6. Website

0/2
  • Deploy the website to Vercel or your own Node.js server.
  • Connect it: set the Website address and the refresh secret, then publish a change and see it appear within a minute.

7. Before you announce it

0/4
  • Buy a coin pack with a test account and check it on Transactions.
  • Send a test push to your own phone.
  • Share a series from the app and tap the link on another phone: the app opens on that series.
  • Check Admin Panel›System›System shows no failed jobs.
tip

Steps 1 and 5 can run in parallel if two people are working: the app only needs the server's address, which you know before the server is finished.
