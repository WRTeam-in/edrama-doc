The **Audit log** records every important change: sign-ins, price changes, refunds, role changes, review decisions, settings and more. It's **append-only**: nobody can edit or delete a row, not even the Owner, and the database itself refuses changes to it.

## What's recorded

A few examples of the actions you'll see:

| Area | Examples |
|---|---|
| **Access** | Signed in, sign-in failed, locked out, password changed, member added, role changed, two-factor turned on, invite sent or revoked |
| **Money** | Purchase refunded, charged back, balance adjustment requested/approved, coin pack changed, VIP plan changed, exchange rate saved, transactions exported |
| **Content** | Title status changed, price changed, owner changed, episodes reordered, short episode allowed, publish time changed, Home layout published, review decisions, comments removed |
| **Settings** | Branding changed, features changed, maintenance mode changed, integration keys changed, legal page published, email template changed |
| **Viewers** | Account banned or unbanned, region changed, episodes granted, contact details viewed |

Each entry keeps the **reason** given, the **IP address**, and in **Details**, the **before and after** of every changed field. Fields named like *password*, *token*, *secret* or *key* are always masked.

## Export

**Export** downloads the filtered rows, newest first, as a CSV file through a signed link that works for five minutes. The export is itself recorded in the log.

:::note[To confirm]
The project notes say audit rows are meant to be kept for two years, but no task currently deletes old rows. They're kept indefinitely until a retention rule is added.
:::
