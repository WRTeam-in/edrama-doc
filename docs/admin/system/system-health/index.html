System

System shows the health of eDrama's background work: whether the scheduler's cron is running, every scheduled task's last run, the queues, and failed jobs you can retry.

Permission area: Settings
  • View See System
  • Edit Retry and delete failed jobs

Sections​

SectionWhat it shows
Server setupWhether the cron is running and how to set it up. If EDRAMA_QUEUE_WORKER_SCHEDULED is off, also the worker command to keep running under supervisor. See Cron & queues.
Scheduled tasksEvery task from the schedule. A task that's late asks whether the scheduler's cron is running.
QueuesWaiting and running jobs per queue (webhooks, notifications, default, video, reports) and the oldest waiting since.
Failed jobsNewest first, with the first line of the error. Retry puts one back on its queue; Retry all does them all; Delete removes one that no longer needs to run.

When a task or job fails, the team is alerted by email, Slack and the bell (at most once per job per 15 minutes). Set where alerts go in Admin Panel›Settings›Notifications›System alerts.

Warnings​

System checks the server and shows a red card when something is unsafe:

WarningFix
The .env file can be opened from the webPoint the domain at the public folder, or upload the package's .htaccess. Then change the database password and replace APP_KEY (put the old one in APP_PREVIOUS_KEYS). The check runs once an hour.
This server isn't set up as a live serverSet APP_ENV=production and APP_DEBUG=false in .env, then run the commands shown.
Visitors reach the app through a proxy it doesn't trustAdd EDRAMA_TRUSTED_PROXIES=cloudflare (behind Cloudflare) or * (behind your host's CDN or load balancer) to .env.

The "not set up as live" warning also appears on the Dashboard's Needs attention.

Server logs​

Server logs opens the log viewer, where developers can read the application's logs. Logs are JSON lines with a request ID, and passwords, tokens, receipts and codes are masked.
